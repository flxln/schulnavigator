**2. Änderungslog-Einträge (Pre-Mortem Fixes)**

**3. Entscheidungstabelle**
Alle Architekturentscheidungen aus dem Plan spiegeln sich exakt im Code wider:
- **Minimaler Create-Block:** Beim POST wird der Block exakt wie spezifiziert angelegt (`figuren: ['frieda', 'otto'], segmente: [], gruppen: []`).
- **Validator-Lockerung:** `segmente.length > 0` ist keine Pflicht mehr, leere Arrays sind zulässig.
- **Delete-Guard (DIALOG_IN_USE):** Die `removeDialog`-Funktion bricht zuverlässig ab, wenn noch Flat- oder Sphere-Dialog-Hotspots existieren.

**4. Scope**
Der Code hält sich strikt an die im Plan definierten Grenzen. Es wurden keine unautorisierten Refactorings oder tangentialen Feature-Erweiterungen (wie z.B. Audio-Upload UI aus #200) vorgenommen.
